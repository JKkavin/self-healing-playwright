healer — Self-Healing Playwright Automation

Version: 0.1.0   |   Powered by: Google Gemini   |   Requires: Python 3.11+

1. Overview

healer is a self-healing layer for Playwright automation. When a locator or API key breaks, it uses Google Gemini to find the correct replacement, caches it, and retries — without changing your test code.

Example log line:

⚠️ If confidence < 0.7, a warning prints so a human reviews.

3.3 healer/cache.py — Locator Cache

Persistent storage for healed locators. First heal costs an AI call; every future run hits the cache for free.

FunctionPurpose
get_cached(failed_locator, page_url)Look up a previous heal
save_cached(failed_locator, page_url, healed_locator, confidence)Store a new heal

Cache file: healed_locators.json

{
  "https://example.com::#password": {
    "locator": "#passcode",
    "confidence": 0.98
  }
}

Stale cache handling: If the cached locator itself fails, the healer re-asks the AI and updates the cache.

3.4 healer/locator.py — The Engine

Extracts DOM, prompts Gemini, parses response, performs action, orchestrates heal-on-failure.

get_dom_snapshot(page)

Extracts only interactive elements. Captures:

  • Tags: input, button, a, select, textarea
  • Roles: button, menuitem, link, tab
  • Attributes: tag, type, id, name, placeholder, text, aria_label, role

Text truncated to 80 chars for small payloads.

heal_locator(page, failed_locator, action_type, value)

Sends DOM snapshot + failed locator to Gemini. Returns (new_locator, confidence).

_perform(page, locator, action, value, timeout)

Supported actions: fill, type, click, check, uncheck, select_option, press, text_content, inner_text.

self_healing_action(page, locator, action, value)

The 5-step flow:

  1. Try original locator
  2. Try cache
  3. Ask AI (if cache miss or stale)
  4. Save to cache + log
  5. Retry with healed locator

Model fallback order

MODEL_FALLBACKS = [
    "gemini-3.8-flash",         # primary
    "gemini-3.7-flash",         # fallback 1
    "gemini-flash-latest",      # fallback 2
    "gemini-flash-lite-latest"  # fallback 3
]

On 503 UNAVAILABLE → retry same model. On 404 NOT_FOUND → skip to next model.

3.5 healer/page.py — Drop-in Wrapper

Lets you write normal Playwright code that self-heals.

HealingPage

Methods returning a HealingLocator:

  • locator(selector)
  • get_by_role(role, name=...)
  • get_by_text(text)
  • get_by_label(label)
  • get_by_placeholder(placeholder)
  • get_by_test_id(test_id)

Everything else passes through: goto, wait_for_timeout, expect_popup, expect_download, _page, etc.

HealingLocator

Healed actions: fill, type, click, check, uncheck, select_option, press, text_content, inner_text.

Pass-through (no healing): hover, wait_for, bounding_box, etc.

Timeout: 5 seconds per attempt.

3.6 healer/api.py — API Key Healing

Same pattern as locators, but for JSON response keys.

self_healing_get(data, key, endpoint)

Like data[key], but heals if the key changed. Returns the value, or raises KeyError if healing fails.

Flow

  1. If key in data → return value
  2. If cache has a mapping and the new key exists → return cached value
  3. Send JSON to Gemini, ask: "Which key replaces 'X'?"
  4. If AI returns NO_MATCH → raise KeyError
  5. Otherwise cache, log, return

API cache file: api_cache.json

{
  "https://api.example.com/user/123::user_id": {
    "key": "id",
    "confidence": 0.99
  }
}

10. Spoken Explanation — Each File in Plain English

Read this out loud if you want a voiceover. Each section is one paragraph describing what a file does, without jargon.

10.1 Overview

This package is called healer. It's a helper library for Playwright automation. When a locator in a test breaks, or when an API response key changes, healer asks Google Gemini to find the right replacement, saves it, and tries again. Your test code doesn't need to change — the healing happens behind the scenes.

10.2 __init__.py — The Front Door

Think of this file as the front door of the package. It's what you see and use from outside. Everything a user needs to import comes from here — the HealingPage class, the self_healing_action function, and the self_healing_get function. The rest of the files are implementation details. When someone types "from healer import HealingPage", this file is what answers. It's short and simple — just a list of exports.

10.3 log.py — The Diary

This file keeps a diary. Every time the healer fixes something, it writes one line to a file called healing_log.jsonl. Each line records what action was attempted, the old broken locator, the new healed locator, which page it happened on, whether the fix came from the AI or from the cache, and how confident the AI was. If the AI's confidence is very low — below 0.7 — the log prints a yellow warning. That's a signal for a human to look at it. The diary is append-only, so nothing ever gets overwritten. It grows into a complete history of every heal that has ever happened.

10.4 cache.py — The Memory

This file is the healer's memory. The first time a locator breaks, the AI has to figure out the fix — that takes a second or two and uses an API call. The cache saves that fix so the next time, the healer doesn't need to ask the AI again. It just looks it up. The cache is stored in a file called healed_locators.json. Every entry has a key — the broken locator plus the page URL — and a value containing the healed locator and the confidence score. There's one clever detail: if the cached locator ever stops working too, the healer notices and quietly asks the AI for a fresh fix. So the cache never goes stale.

10.5 locator.py — The Brain

This is the most important file. It's the brain of the healer. It does the actual work. First, it takes a snapshot of the page — but not the whole page. It only grabs the interactive elements: inputs, buttons, links, menus. That keeps the payload small and helps the AI focus. The snapshot includes things like the element's id, name, placeholder, aria-label, and role. Then, when a locator fails, it sends that snapshot to Gemini along with the failed locator and the action that was attempted. It asks Gemini: given this page, what should the new locator be? Gemini replies with a CSS selector and a confidence score. The file then handles the retry logic: try the original locator, try the cache, ask the AI, save the result, retry with the healed locator. It's the five-step healing flow in one place. There's also a safety net. Google sometimes retires model names or has temporary outages. This file tries four different Gemini models in order and handles both 503 errors and 404 errors. So the healer keeps working even when Google's API is having a bad day.

10.6 page.py — The Drop-in Wrapper

This file is what makes adoption easy. It defines two classes: HealingPage and HealingLocator. HealingPage wraps a regular Playwright page. When your code asks for a locator — say, page.get_by_role with the name Submit — instead of returning a normal Playwright locator, it returns a HealingLocator. That wrapper looks exactly like a normal locator to your code, but underneath it has healing powers. HealingLocator intercepts the actions you perform — fill, click, check, and so on. When you call dot click, it first tries the normal way. If that times out, it quietly asks the healer to find the right element, then retries. Your test code never sees the difference. The beauty is that you don't have to rewrite your tests. You just change one line — instead of page equals context dot new page, you write page equals HealingPage of context dot new page. Everything else stays the same.

10.7 api.py — API Healing

This file applies the same idea to API responses. Sometimes an API changes its response shape — for example, user_id becomes id, or token becomes auth_token. Your test then crashes with a KeyError. self_healing_get is a drop-in replacement for data of key. If the key is missing, it checks its own cache, then asks Gemini which key in the response most likely replaces the old one. It caches the mapping in api_cache.json so future runs are instant. It's the same pattern as locators — first try, then cache, then AI — but for JSON keys instead of DOM elements.

10.8 Summary

Six files. Each has one clear job. The init file is the front door. The log file is the diary. The cache file is the memory. The locator file is the brain. The page file is the wrapper. The api file handles API healing. Together, they form a self-healing layer for Playwright. When a locator or API key breaks, the healer finds the fix, remembers it, and keeps your test running — without you having to change a line of test code.
